## See Reedwork in action

Reedwork lets you define a command without manually registering it with
the server.

```java
@Command(
value = "hello",
description = "Say hello"
)
public final class HelloCommand {

    @CommandHandler
    public boolean execute(CommandContext context) {
        context.player().sendMessage(
            Component.text("Hello, Reedwork!")
        );

        return true;
    }
}
```

The command is discovered and registered automatically when your plugin
scans its components.

## How Reedwork works

Reedwork does not try to take control of your application architecture.

Instead, it provides the infrastructure around your plugin components:

<Steps>
1. **Discover**

   Reedwork scans your plugin package and discovers supported components.

2. **Resolve**

   Dependencies are automatically resolved through Reedwork's dependency injection system.

3. **Register**

   Commands, listeners, enchantments, and other supported components are registered with Paper automatically.
</Steps>

## Dependency injection without the boilerplate

Dependencies are resolved automatically, allowing your plugin components to remain focused on their actual responsibilities.

```java
@Command("hello")
public final class HelloCommand {

    private final GreeterService greeterService;

    public HelloCommand(GreeterService greeterService) {
        this.greeterService = greeterService;
    }

    @CommandHandler
    public boolean execute(CommandContext context) {
        greeterService.sendGreeting(context.player());
        return true;
    }
}
```

No service locator.
No manual wiring.
Just constructor dependencies.
